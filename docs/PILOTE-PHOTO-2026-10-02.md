# Pilote photo du 2 octobre 2026

La clé OpenAI du serveur dispose maintenant de crédits. Une recette privée a produit une vraie retouche d'un exemple du site : 1 024 × 768 pixels, avec un coût estimé de 0,024375 $ pour cet appel. La photo a été contrôlée visuellement : les ouvertures, le radiateur et le mobilier restent cohérents ; la lumière et quelques détails de présentation changent. L'analyse et la reformulation de la demande ont également répondu. Cette seule recette ne valide pas encore la qualité de toutes les pièces ni le coût d'une correction et d'un fichier HD.

Le moteur photo est activé **uniquement pour le compte propriétaire actif** `martinmorebkk@gmail.com`. Le contrôle est effectué sur les routes serveur d'analyse, d'essai et de génération HD, et non seulement sur les boutons. `/api/sante` indique la retouche disponible à la session du propriétaire et indisponible sans session ou avec un autre compte. Les fichiers HD déjà produits restent récupérables. La configuration est `IA_ACTIVE=true`, `IA_PUBLIQUE=false`, `FOURNISSEUR_IMAGE=openai` ; les clés restent dans `~/studioapi/.env`, hors de la racine publique.

Une nouvelle clé Higgsfield réservée au serveur est installée dans ce même `.env`. Son authentification a répondu en HTTP 200 à une estimation du modèle Seedance image-vers-vidéo, sans lancer ni facturer de vidéo. La clé n'est pas présente dans le dépôt. Le moteur vidéo du produit reste désactivé : l'authentification seule ne constitue pas une génération vidéo utilisable.

Les 97 tests API passent dans une copie isolée du code sur l'hébergement, dont 30 tests photo. Le nouveau test vérifie qu'un compte client reçoit 503 pour l'analyse, l'essai et la HD, tandis que le propriétaire peut analyser et générer un aperçu. Après publication, le contrôle réel de `/api/sante` a renvoyé `retouche_disponible=true` avec une session existante du propriétaire et `false` sans session ou avec un jeton invalide ; une requête photo anonyme a renvoyé 401. L'essai de génération depuis l'interface de production avec une photo du compte n'a pas été effectué pendant cette publication.

La publication a modifié seulement cinq modules API et trois réglages du `.env`, puis redémarré Passenger. Les versions antérieures des fichiers et la configuration privée sont conservées dans `~/sauvegardes-studio/pilote-photo-20261002/`, accessible au seul compte d'hébergement. Le site et l'aperçu mobile continuent d'utiliser le même état de disponibilité par compte. Aucun export web ou mobile n'a été modifié.

Les paiements et la génération vidéo restent fermés. Stripe n'est pas configuré ; l'API refuse donc tout achat. Avant d'ouvrir la photo à tous les comptes, il faut vérifier plusieurs photos et corrections dans le vrai parcours, mesurer les coûts, prévoir un stockage de production pour les fichiers et tester le paiement de bout en bout. Les sauvegardes historiques n'ont pas été supprimées pour gagner de la place.
