# Aperçus photo mieux protégés — 6 octobre 2026

Martin trouvait les filigranes des photos payantes trop discrets. Le fichier d'aperçu généré par le serveur porte maintenant un motif plus grand, plus dense et lisible sur les zones claires comme sombres, avec une légère atténuation de l'image. La couche de l'interface web est aussi renforcée. Le composant mobile a été préparé dans le code, mais son nouvel export n'a pas été déployé pour ne pas écraser le bundle mobile publié séparément pendant les changements de paiement. Le mobile reçoit toutefois immédiatement le nouvel aperçu filigrané du serveur.

La protection concerne uniquement les versions payantes non acquises. L'original du client, sa photo offerte, les versions acquises et les téléchargements HD restent sans filigrane. La résolution de l'aperçu est inchangée ; la netteté des fichiers achetés est préservée. Le motif reste une dissuasion, pas une garantie contre toute capture d'écran.

Deux anciens aperçus clients ont été recalculés depuis leurs versions propres vers de nouvelles clés du stockage privé. Les anciennes copies restent conservées. La sauvegarde de SQLite, de l'ancien code serveur et des fichiers web remplacés se trouve dans `/Users/more/Documents/Codex/studio-annonce-backups/filigrane-20261006/`. La sauvegarde SQLite a passé `integrity_check`. Après migration, 2 références d'aperçus ont changé, 0 référence de fichier propre ou HD a changé, et le nombre de photos est resté à 37. Une seconde exécution à blanc ne trouve plus rien à migrer.

Contrôles : 158 tests API, build et tests web, typecheck et 23 tests mobiles réussis ; nouvel export web publié seulement pour `/app/photo/` et ses ressources, sans suppression des anciens fichiers. Les empreintes des pages web et du code serveur concordent avec les fichiers publiés. `/api/sante` répond 200 et les photos privées refusent une requête anonyme (401). La fonction de filigrane a été exécutée sur le serveur avec sa police disponible. Le module de paiement, la configuration Stripe, `.env` et les soldes ne sont pas modifiés.

Un exemple visuel produit à partir d'une image publique de démonstration, sans photo client, est conservé dans `filigrane-20261006/apercu-exemple.webp` sous le dossier de sauvegarde ci-dessus. La vue authentifiée d'une photo cliente n'a pas été ouverte pour cette vérification.

## Explication du filigrane — 7 octobre 2026

Martin conserve le filigrane intermédiaire. Le texte du parcours précise désormais que seul l'aperçu d'une retouche payante non acquise est filigrané : la photo gardée et téléchargée en HD est nette, sans filigrane, et son nouveau téléchargement ne consomme pas un second crédit. Cette explication est placée sous l'aperçu, sur le bouton et la confirmation de récupération, dans l'aide, les tarifs, la facturation et le parcours mobile. La règle de crédit photo et le code Stripe n'ont pas changé.

Le build web, le lint web (aucune erreur, avertissements existants), le typecheck et le lint mobile, ainsi que les 23 tests mobiles passent. Les pages publiques Aide et Tarifs ont été vues dans le navigateur après publication. L'application mobile web se charge également. Les pages et ressources privées ont été vérifiées par empreinte sur le serveur ; l'écran photo authentifié n'a pas été rejoué visuellement avec un compte client.

Pour conserver les changements publiés en parallèle sur le compte et les paiements, la livraison N0C a été ciblée : les pages Aide/Tarifs ont été exportées depuis le dépôt, tandis que les ressources actives des écrans Photo, Facturation et Mobile ont reçu uniquement les changements de texte ou le composant photo concerné. Les fichiers partagés et le code Stripe déjà en ligne n'ont pas été remplacés. Le nouvel export complet de l'application mobile et le composant complet de facturation du dépôt n'ont pas été substitués aux versions en ligne : leurs sources doivent être réconciliées avec les changements parallèles avant le prochain déploiement intégral.

Les sauvegardes préalables des pages publiques, de la fiche photo, de Facturation/Compte et du bundle mobile actif sont conservées sur le serveur sous `~/sauvegardes-studio/explication-filigrane-20261007/`. Les anciennes ressources restent disponibles pour les sessions déjà ouvertes.
